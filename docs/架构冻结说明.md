# 服务器与终端架构冻结说明

## 冻结版本

本文件用于约束后续开发，未经双方确认不得改变服务器1、服务器2和终端程序的职责边界。

## 三个程序

### `terminal/`

独立终端程序。由终端程序负责人维护。负责用户界面、上传、任务提交、状态查看、结果请求、结果下载和审计查询。终端不直接连接数据库、加密卷、沙箱、水印算法或区块链节点。

### `server1/`

接入与控制面程序。负责认证、项目权限、终端数据接收、上传校验、任务和流转管理、服务器2任务编排、状态查询和业务审计查询。服务器1不长期保存原始测绘数据，不执行大型测绘算法，不输出服务器2原始数据。

### `server2/`

数据处理与结果输出面程序。负责加密存储、沙箱、计算、水印、结果审核、只读结果接口、PostGIS、处理侧审计和区块链存证适配。服务器2不接收终端原始上传，不提供任意文件读取。

## 固定数据流

```text
终端上传/提交请求 → server1
server1转交已校验数据和任务 → server2
server2完成存储/计算/水印/审核 → server2
终端读取审核通过结果 → server2只读接口
server2回传状态/结果索引/凭证 → server1
```

## 固定访问策略

- 终端到服务器1：只开放接收和控制业务接口。
- 终端到服务器2：只开放结果输出、授权地图/模型服务和追溯查询。
- 服务器1到服务器2：只开放内部数据转交、任务控制、状态查询和事件接口。
- 数据库、文件目录、VeraCrypt、沙箱、Elasticsearch管理端口、FISCO BCOS管理端口均不对终端开放。

## 技术方案对应

| 方案内容 | 固定归属 |
|---|---|
| 安全接入区、Gateway、JWT鉴权 | server1 |
| 数据上传、项目、任务、流转控制 | server1 |
| VeraCrypt项目加密分区 | server2 |
| AppContainer Sandbox-Plus/受控计算 | server2 |
| 产品运行空间和研发空间 | server2 |
| GDAL脱敏和坐标精度降低 | server2 |
| GeoTIFF、SHP/GeoJSON、DLG、OSGB水印 | server2 |
| PostGIS数据侧元数据和空间索引 | server2 |
| 审核通过结果只读输出 | server2 |
| Sysmon数据处理主机审计 | server2 |
| 业务审计查询 | server1 |
| 处理/主机日志接入 | server2 |
| Kibana/ElastAlert业务展示和告警联动 | server1协调，server2提供日志 |
| FISCO BCOS归属/流转登记 | 两台服务器按节点和适配角色分担 |
| 取证链条和溯源报告 | server1提供查询入口，server2提供证据 |

## 测试和生产

测试环境允许开发人员通过远程桌面连接两台服务器；生产环境使用甲方内网交换机、VLAN或防火墙。环境地址和端口只能来自配置，不能写入程序。

## 不允许的架构漂移

- 不把终端程序并入server1或server2目录。
- 不让server1逐渐承载水印、沙箱和大型文件处理。
- 不让server2直接承担用户登录和终端上传入口。
- 不让终端直接连接数据库或挂载服务器加密卷。
- 不通过普通文件共享代替server2只读结果接口。
