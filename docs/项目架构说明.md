# 项目架构说明

## 1. 架构定位

本项目是一套统一的平台程序，不区分“服务器程序”和“台式机程序”两套业务系统。

同一套平台可以部署在服务器、台式机、涉密网节点或政务网节点上。部署时通过配置启用不同角色，从而形成单机闭环或多节点闭环。

```text
统一平台程序
├── 用户界面
├── 接入与控制
├── 数据存储与元数据
├── 沙箱计算
├── 四类水印
├── 结果输出
└── 审计、告警、区块链和溯源
```

## 2. 角色不是设备

服务器和台式机都可以承担以下角色：

- 接入/控制角色；
- 处理/存储角色；
- 只读输出角色；
- 审计/存证角色；
- 用户界面角色。

设备类型只影响性能和部署方式，不决定业务架构。服务器之间的流转和台式机之间的流转都使用同一套协议。

## 3. 单机闭环

适用于一个独立涉密网或政务网环境只有一台设备的情况：

```text
用户台式机/服务器
        │
        ▼
统一平台程序
├── 接收数据
├── 权限校验
├── VeraCrypt加密存储
├── 沙箱计算
├── 四类数据水印
├── 结果审核和只读输出
├── Elasticsearch/告警
├── FISCO BCOS存证
└── 溯源报告
```

用户通过本机浏览器或客户端操作，数据在该网络内部完成闭环。

## 4. 双节点闭环

适用于需要把接入、处理和结果输出分开时：

```text
节点A：统一平台程序
启用用户界面 + 接入/控制角色
        │
        │ 统一内部协议
        ▼
节点B：统一平台程序
启用处理/存储 + 只读输出 + 审计/存证角色
```

节点A和节点B可以是两台服务器，也可以是两台台式机。不要复制三套业务代码；只使用不同配置启动相同平台的不同角色。

## 5. 用户端

用户端也是统一平台的一部分，可以有两种运行方式：

### 浏览器方式

用户界面文件部署在平台节点上，台式机通过浏览器访问。用户端不安装数据库、水印算法或沙箱。

### 独立客户端方式

`terminal/` 保存独立客户端实现。客户端使用公共接口调用接入/控制角色和只读输出角色，但不复制服务器端处理逻辑。

两种方式使用相同的认证、任务、结果和审计协议。

## 6. 技术方案对应

### 数据来源和存储

- GeoTIFF、OSGB、SHP/GeoJSON、DLG原始文件存入项目专属VeraCrypt加密空间；
- PostgreSQL/PostGIS只保存文件路径、范围框、坐标系、分辨率、哈希等元数据和空间索引；
- 原始大文件不作为数据库内容保存。

### 隔离计算

- 使用AppContainer Sandbox-Plus或等效受控计算方式；
- 按项目区分产品运行空间和研发空间；
- 使用安全计算引擎调用文件库、算法库和PostGIS；
- 使用GDAL进行按需脱敏和坐标精度降低；
- 任务完成后清理临时文件并按策略卸载加密卷。

### 四类水印

- GeoTIFF：DWT+DCT+SVD频域水印，保留坐标系和投影；
- SHP/GeoJSON：属性表增加AES加密标识字段；
- DLG：文件头注释或元数据区增加加密标识；
- OSGB/OBJ：JPG/PNG纹理像素层DCT水印，不改几何和顶点坐标。

### 流转、审计和溯源

- 流转控制使用认证、项目权限和JWT/短时授权令牌；
- Elasticsearch保存日志，Kibana查询展示，ElastAlert2进行异常告警；
- FISCO BCOS保存归属登记和流转登记等关键凭证；
- Sysmon采集Windows主机行为；
- 水印、日志和链上凭证共同生成取证和溯源报告。

## 7. 涉密网和政务网

涉密网和政务网是两个部署环境，不等同于“台式机”和“服务器”。每个环境都可以采用单机闭环或双节点闭环。

- 涉密网：重点落实物理隔离、国密证书和审计；
- 政务网：重点落实逻辑隔离、TLS和GeoServer在线服务；
- 两个环境是否交换数据，按照甲方安全管理要求使用网闸、安全交换或人工摆渡。

## 8. 配置要求

由配置决定：

- 当前节点启用的角色；
- 接入节点地址；
- 处理节点地址；
- 只读输出地址；
- 数据目录和加密卷目录；
- 数据库、日志和区块链服务地址；
- 测试或生产环境；
- 终端数量预留。

不能把客户IP、密码、证书、密钥、用户目录或开发机路径写入代码。
