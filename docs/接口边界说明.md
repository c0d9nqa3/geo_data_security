# 统一平台接口边界说明

## 1. 接口设计原则

服务器、台式机、涉密网节点和政务网节点运行同一套平台程序。接口按角色区分，不按设备名称区分。

角色包括：

- `access/control`：接入和业务控制；
- `processing/storage`：处理和存储；
- `readonly-output`：审核结果只读输出；
- `audit/proof`：审计、告警、链上存证和溯源；
- `terminal-ui`：用户操作界面。

一个设备可以启用多个角色；双节点部署时再将角色拆到不同设备。

## 2. 用户界面到接入/控制角色

允许：

- 登录和身份认证；
- 项目创建和查询；
- 数据导入申请；
- 任务提交；
- 任务状态查询；
- 审核申请；
- 流转和权限查询。

不允许：

- 直接连接数据库；
- 直接读写服务器文件系统；
- 直接挂载VeraCrypt；
- 直接调用水印算法；
- 直接调用沙箱管理接口。

## 3. 用户界面到只读输出角色

允许：

- 读取审核通过的指定结果；
- 下载指定结果；
- 访问授权的GeoServer地图/模型服务；
- 查询追溯记录；
- 下载追溯报告。

每次请求必须校验：用户身份、项目权限、结果ID、审核状态、授权令牌和有效期。

禁止：

- 上传原始数据；
- 目录列表；
- 任意路径读取；
- 读取其他项目数据；
- 读取未审核结果；
- 访问数据库和管理端口。

## 4. 接入/控制角色到处理/存储角色

允许：

- 转交已校验的数据；
- 创建受控计算任务；
- 查询任务状态；
- 发送审核和流转信息；
- 查询结果索引；
- 接收处理状态和凭证信息。

要求：

- 使用服务间身份认证；
- 请求带版本号、请求ID和任务ID；
- 校验项目ID、文件哈希和授权状态；
- 支持超时、重试和幂等；
- 不允许把本地命令直接传给处理节点。

## 5. 处理/存储角色内部

处理/存储角色内部完成：

- VeraCrypt项目卷管理；
- 项目运行空间和研发空间；
- AppContainer/受控计算；
- GDAL脱敏和坐标精度降低；
- 四类数据水印；
- PostgreSQL/PostGIS元数据和空间索引；
- 结果审核前检查；
- 原始数据、处理数据和结果生命周期管理。

原始数据不进入数据库；数据库只保存元数据和空间索引。

## 6. 审计和存证接口

统一记录：

`user_id`、`project_id`、`file_id`、`task_id`、`result_id`、`watermark_id`、操作类型、时间、源哈希、结果哈希、审核状态和处理状态。

审计事件可以由各角色产生，但使用同一事件格式。关键事件经过FISCO BCOS适配写入链上凭证。

## 7. 单机和双节点的接口关系

### 单机

```text
用户界面 → 本机access/control
本机access/control → 本机processing/storage
用户界面 → 本机readonly-output
各模块 → 本机audit/proof
```

### 双节点

```text
节点A用户界面/access/control
        ⇄ 内部协议
节点Bprocessing/storage/readonly-output/audit/proof
```

服务器到服务器、台式机到台式机使用相同协议。具体地址、端口和TLS由配置提供。
