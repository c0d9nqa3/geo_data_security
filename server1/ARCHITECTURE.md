# server1 服务程序

服务器1程序的源码目录。当前按**模块化单体**组织：一个 Spring Boot 进程，业务按 Maven 模块拆分。后续可以在不改变接口的前提下拆分服务。

`app/` 是唯一启动入口，依赖并组装下列模块：

1. `gateway/`：终端业务接入（鉴权、限流、统一错误、访问日志）。不实现具体业务，也没有启动类。
2. `auth/`：登录、JWT、用户角色权限。
3. `circulation/`：新建项目、上传文件、提交任务自动进入流转待办；管理员审批通过后可向服务器2提交分发授权。
4. `ingest/`：终端数据接收 / 文件管理（上传索引、校验、转交）。
5. `project/`：项目和成员管理。
6. `task/`：任务创建、调度、状态。
7. `audit/`：业务审计事件产生、提交与追溯查询。

支撑：

- `common/`：统一响应、请求上下文（不被终端直接访问）。
- `web/`：前后端分离的前端工程（Vue）。页面功能按上列模块划分 API：`web/src/modules/{auth,circulation,ingest,project,task,audit}/`

组织方式：模块化单体 + 前后端分离。`web` 只通过 REST 调 `app` 进程（端口 8081）的 `/api`，请求先经 gateway 过滤器，再落到各业务模块。

不在本目录实现水印算法、沙箱执行器和原始数据存储。
