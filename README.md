# 测绘地理信息数据安全平台

## 这是本项目的架构基线

本仓库包含三个独立的软件部分：

```text
terminal/  ── 终端程序
server1/   ── 服务器1程序：接入与控制面
server2/   ── 服务器2程序：数据处理与输出面
```

终端程序由独立成员负责，但代码和接口契约统一放在本仓库，便于联调和版本管理。

## 已冻结的业务方向

```text
终端程序
  ├── 上传数据、提交请求 ───▶ 服务器1
  └── 读取审核通过结果 ────▶ 服务器2（严格只读）

服务器1 ─── 内部任务/数据协议 ───▶ 服务器2
服务器2 ─── 状态/凭证回传 ───────▶ 服务器1
```

这不是三套独立系统。三部分共同完成数据导入、项目隔离、受控计算、水印、审核、流转、审计和追溯。

## 服务器1：接入与控制面

服务器1的边界是“控制业务流程”，不是承载全部数据处理。

负责：

- 终端登录和身份认证；
- 用户、角色和项目权限；
- 接收终端上传数据；
- 上传大小、格式、哈希和基础完整性检查；
- 项目、文件、任务和流转单据管理；
- 创建和调度处理任务；
- 向服务器2转交已校验的数据和授权任务；
- 接收服务器2的状态、结果索引和链上凭证；
- 审核申请、审批状态和输出授权；
- 提供终端查询任务状态和审批状态的接口；
- 提供业务审计查询和溯源查询入口。

服务器1不负责：

- VeraCrypt项目加密卷的长期存储；
- 大型GeoTIFF/OSGB/SHP/DLG处理；
- 四类水印算法执行；
- 沙箱内部执行；
- 终端原始结果文件的直接输出；
- 服务器2原始数据目录的访问。

## 服务器2：数据处理与结果输出面

服务器2的边界是“保护和处理数据，并输出审核通过的结果”，不是承载用户和业务入口。

负责：

- 接收服务器1转交的已校验数据和处理任务；
- 挂载和卸载项目专属VeraCrypt加密卷；
- 项目运行空间和研发空间；
- AppContainer Sandbox-Plus或等效受控计算；
- 安全计算引擎、文件库、算法库和GDAL；
- GeoTIFF、SHP/GeoJSON、DLG、OSGB四类数据水印；
- 原始数据、处理数据和审核结果的加密存储；
- PostgreSQL/PostGIS元数据和空间索引；
- 结果审核前的技术检查；
- 面向终端的严格只读结果输出；
- 授权GeoServer地图/模型服务；
- Sysmon主机行为采集；
- 计算和文件行为审计；
- FISCO BCOS链上归属和流转存证适配；
- 结果水印证据、链上凭证和取证材料。

服务器2不负责：

- 终端原始数据上传；
- 终端用户登录主入口；
- 任意目录浏览或路径下载；
- 对终端开放数据库、文件共享、沙箱管理和区块链管理端口。

## 横向能力的分配

为了避免一台服务器职责过重，横向能力按以下方式分配：

| 能力 | 服务器1 | 服务器2 |
|---|---|---|
| 用户认证、角色权限、项目权限 | 主责 | 校验授权结果 |
| 终端上传 | 主责 | 不接收终端上传 |
| 任务创建和调度 | 主责 | 执行任务 |
| 原始大文件存储 | 不长期保存 | 主责，VeraCrypt加密卷 |
| PostGIS | 只使用业务索引 | 承载数据侧元数据/空间索引 |
| 四类水印 | 任务编排和状态 | 算法执行和结果生成 |
| 沙箱 | 创建任务请求 | 主责，运行隔离任务 |
| 结果审核状态 | 业务审批 | 技术检查和结果准备 |
| 结果输出 | 不直接输出原始结果 | 主责，只读输出 |
| Elasticsearch | 业务审计查询和索引协调 | 计算/文件/主机日志采集 |
| Kibana/告警 | 告警查询入口和业务展示 | 服务器2日志接入 |
| FISCO BCOS | 业务事件编排和凭证查询 | 处理事件适配和节点承载预留 |
| Sysmon | 可选控制面日志 | 主责，数据处理主机审计 |

FISCO BCOS的4节点PBFT不能简单理解为某一台服务器独占全部节点。仓库只预留节点和适配接口；真实节点、证书和私钥的部署位置由甲方网络和区块链参与方确认。

## 终端程序

`terminal/` 是独立的软件工程，不由服务器程序目录代替。

终端程序负责：

- 用户登录；
- 项目和文件操作界面；
- 向服务器1上传数据；
- 向服务器1提交处理任务；
- 从服务器1查询任务和审批状态；
- 向服务器2请求审核通过的结果；
- 下载服务器2授权结果；
- 查看审计、流转和溯源信息；
- 调用授权的GeoServer或模型服务。

终端程序不负责：

- 直接读写服务器文件系统；
- 直接连接数据库；
- 直接调用水印算法；
- 直接挂载VeraCrypt；
- 直接控制沙箱；
- 保存服务器密钥和区块链私钥。

## 访问边界

| 来源 | 目标 | 允许 | 禁止 |
|---|---|---|---|
| 终端 | 服务器1 | 登录、上传、项目、任务、状态、审批 | 数据库、系统管理、任意文件访问 |
| 终端 | 服务器2 | 审核通过结果只读下载、授权地图/模型、追溯查询 | 上传、目录列表、原始数据、管理端口 |
| 服务器1 | 服务器2 | 已校验数据转交、任务提交、状态查询、审计/凭证事件 | 任意系统命令和无边界文件访问 |
| 服务器2 | 服务器1 | 状态回传、结果索引、链上凭证、处理通知 | 反向开放用户管理接口 |

## 网络部署

### 测试环境

两台测试电脑可以通过远程桌面分别连接服务器1和服务器2，用于安装、调试和联调。远程桌面是运维手段，不属于业务数据流转接口。

### 生产环境

终端、服务器1和服务器2接入甲方内网交换网络。终端数量按至少11台预留：

```text
终端1...终端11
        │
     内网交换机
      ├── 服务器1：接收/控制
      └── 服务器2：处理/只读输出
```

生产环境可以进一步将终端区和服务器区划分VLAN，并用防火墙只放行：

- 终端 → 服务器1：业务接入接口；
- 终端 → 服务器2：只读结果接口；
- 服务器1 → 服务器2：内部任务接口；
- 服务器2 → 服务器1：状态回调接口。

## 配置要求

测试地址、生产地址、端口、TLS证书、数据库连接、VeraCrypt配置、区块链配置和终端数量都必须通过环境配置注入，不能写死在代码中。

## 代码边界

- `terminal/`：终端程序代码，不放目录说明README。
- `server1/`：服务器1程序代码。
- `server2/`：服务器2程序代码。
- `shared/`：三方必须一致的接口、模型、事件和错误码。
- `docs/`：冻结架构、接口、部署和验收说明。
- `deploy/`：服务器和终端部署说明。
- `tests/`：接口、安全、数据完整性、性能、审计和部署测试。
