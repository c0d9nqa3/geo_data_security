# 测绘地理信息数据安全平台

## 项目定位

本项目是测绘地理信息数据安全平台的基础工程骨架，目标是支持数据接收、项目隔离存储、受控计算、四类数据水印、结果审核、只读结果输出、流转审计和追溯存证。

当前阶段只建立项目架构、模块边界和部署约束，不包含可直接用于生产的水印算法、沙箱安全策略或区块链密钥。后续代码必须在真实数据和甲方网络环境中验证。

## 核心数据流

```text
终端
  ├── 上传数据、提交任务 ───────> 服务器1
  └── 获取审核通过结果 ────────> 服务器2（严格只读结果接口）

服务器1 ─── 内部受控接口 ───────> 服务器2
服务器2 ─── 任务状态/凭证回传 ──> 服务器1
```

## 服务器职责

### 服务器1：数据接入与业务控制

负责统一业务入口、登录认证、项目权限、数据上传、任务提交、任务状态、审核申请和业务记录。服务器1不提供服务器2原始数据目录访问，也不对终端提供原始数据读取能力。

### 服务器2：隔离计算与结果输出

负责 VeraCrypt 项目加密卷、沙箱任务、测绘数据处理、四类水印、结果审核、审计基础设施和结果输出。服务器2对终端只开放审核通过结果的只读接口，不接受终端原始数据上传。

## 终端访问规则

- 终端到服务器1：上传、登录、项目管理、任务提交、状态查询。
- 终端到服务器2：审核通过结果下载、授权地图/模型服务、追溯查询。
- 终端禁止访问：数据库、Elasticsearch 管理端口、FISCO BCOS 管理端口、VeraCrypt 盘符、文件共享和沙箱管理接口。
- 生产环境至少预留11台终端；终端数量通过网络和配置扩展，不在代码中写死。

## 目录说明

- `server1/`：服务器1的接入和业务控制模块。
- `server2/readonly_output/`：终端严格只读结果下载、GeoServer在线服务和追溯查询。
- `shared/`：两台服务器共同使用的协议、数据模型、配置模型和错误码。
- `deploy/`：Windows部署、服务启动、初始化和网络配置说明。
- `tests/`：接口、权限、数据完整性、部署和验收测试目录。
- `docs/`：架构、接口、部署和验收文档。
- `config/`：配置模板和环境变量说明，不保存真实密码和密钥。

## 当前不包含

- 生产级安全沙箱认证；
- 未经真实 DLG 格式验证的通用 DLG 水印；
- 未经真实 OSGB 样本验证的通用 Mesh 处理；
- 真实 FISCO BCOS 证书和私钥；
- 客户生产环境 IP、密码、证书和密钥。

## 开发约束

1. 配置通过环境变量或配置文件注入，禁止把地址、密码、密钥写入代码。
2. 服务器2的终端接口只能读审核通过的结果，不能提供上传和目录遍历。
3. 原始测绘文件不进入 PostgreSQL/PostGIS，数据库只保存元数据和空间索引。
4. 任何文件输出都必须绑定用户、项目、任务和审核状态，并写入审计事件。
5. 每完成一个模块，都要用真实运行结果验证，不以“代码已写完”作为完成标准。
