# 测绘地理信息数据安全平台

## 架构基线

本项目不是“服务器一套程序、终端另一套程序”。项目采用一套统一的平台程序：同一套代码、同一套数据模型、同一套接口协议和同一套安全流程，可以部署到服务器，也可以部署到台式机/终端。

部署到不同设备后，通过配置决定该节点承担的功能。设备类型不决定程序类型，部署角色才决定程序启用哪些模块。

```text
统一平台程序
├── 接入节点：接收数据和请求
├── 处理节点：加密存储、沙箱计算、水印处理
├── 输出节点：只读输出审核通过的结果
└── 业务终端节点：提供用户操作界面
```

同一节点可以按部署需要组合多个角色。例如在单机闭环环境中，一台服务器或台式机可以同时启用接入、处理、输出和用户界面；在双机环境中，再按配置拆分到两台设备。

## 两种流转关系使用同一套架构

### 服务器与服务器之间

```text
服务器A：接入/控制
        ⇄ 统一内部接口
服务器B：处理/存储/输出
```

### 台式机与台式机之间

```text
台式机A：接入/控制
        ⇄ 统一内部接口
台式机B：处理/存储/输出
```

两种场景使用相同的：

- 用户认证和权限模型；
- 项目、文件、任务和结果模型；
- 数据导入协议；
- 任务协议；
- 只读结果输出协议；
- 水印处理流程；
- 审计事件格式；
- 区块链存证接口；
- 配置方式。

区别只在于节点的硬件、网络地址、启用模块和运行方式。

## 统一平台程序的组成

```text
platform/
├── common/       公共模型、协议、认证、审计和配置
├── access/       数据接入、用户界面和API入口
├── processing/   加密存储、沙箱、计算和水印
├── output/       审核结果只读输出和在线服务
├── audit/        日志、告警、链上存证和取证
└── deployment/   Windows服务和节点角色启动方式
```

仓库现有目录仍按 `server1/`、`server2/`、`terminal/` 组织，是为了表达部署职责和协作边界，不代表最终要维护三套不同的软件。后续写代码时，公共能力必须放入 `shared/`，服务器和终端只装载对应角色模块。

## 节点角色

### 接入/控制角色

负责：

- 用户登录和身份认证；
- 用户、角色、项目和权限；
- 数据接收；
- 文件和任务管理；
- 处理请求创建；
- 审核和流转控制；
- 访问处理节点；
- 用户界面和业务API。

### 处理/存储角色

负责：

- VeraCrypt项目加密卷；
- 产品运行空间和研发空间；
- AppContainer Sandbox-Plus或等效受控计算；
- 安全计算引擎；
- GDAL脱敏和精度降低；
- GeoTIFF、SHP/GeoJSON、DLG、OSGB水印；
- PostgreSQL/PostGIS元数据和空间索引；
- 原始数据、处理数据和结果数据管理。

### 只读输出角色

负责：

- 结果审核后的授权下载；
- GeoServer地图/模型在线服务；
- 追溯查询和报告下载；
- 短时或一次性输出令牌；
- 结果访问审计。

只读输出角色不接受原始数据上传、不提供目录列表、不提供任意路径读取。

### 审计/存证角色

负责：

- Sysmon主机行为采集；
- Elasticsearch日志；
- Kibana检索和展示；
- ElastAlert2异常告警；
- FISCO BCOS归属和流转存证；
- 水印证据和取证链条。

这些角色可以部署在服务器，也可以部署在指定的台式机节点上；生产部署时按客户安全要求决定。

## 单机闭环部署

当一个涉密网或政务网只提供一台设备时，统一程序可以在该设备上启用多个角色：

```text
一台服务器/台式机
├── 用户界面
├── 接入与控制
├── 加密存储
├── 沙箱计算
├── 四类水印
├── 结果只读输出
├── 审计和告警
└── 区块链存证适配
```

用户通过同一设备上的浏览器或客户端访问平台，数据在本机内部完成导入、处理、审核、输出和审计闭环。

## 双节点部署

当需要把接入和处理分开时：

```text
节点A：统一平台程序
启用接入/控制角色

节点B：统一平台程序
启用处理/存储/只读输出/审计角色
```

节点A和节点B仍然运行同一平台的不同配置，不是两套业务系统。

## 涉密网和政务网部署

涉密网和政务网分别属于不同的部署环境。每个环境可以采用单节点闭环，也可以采用双节点部署：

```text
涉密网：平台节点（服务器或台式机）
政务网：平台节点（服务器或台式机）
```

如果两个环境之间需要交换数据，应使用甲方批准的网闸、安全交换或人工摆渡方式，不能默认直接联网。

## 代码约束

1. 终端程序不是另一套业务系统，统一平台的用户界面和节点客户端都使用公共协议。
2. 设备角色通过配置启用，不通过复制和维护三套不同代码实现。
3. `server1/`、`server2/`、`terminal/` 表示部署角色和代码边界，不表示技术栈必须不同。
4. 服务器和台式机之间的流转必须复用同一套协议。
5. 配置、IP、端口、证书、密钥、存储路径和启用模块均不能写死。
6. 原始数据不进入数据库；数据库只保存元数据和空间索引。
7. 结果输出只开放审核通过数据的读取接口。
